# 库结构与维护

## 一、目录结构

默认根目录 `~/Desktop/知识卡片库`（解析顺序：`KCARD_HOME` > `DSH_CARDS_HOME` > 默认）。库根可用 `KCARD_HOME` 指向任意位置。

```
知识卡片库/
├── catalog.json              # 机器索引，由 reindex 生成，勿手改
├── INDEX.md                  # 人读索引：书架总览 + 分书架卡片表 + 标签云
├── 浏览.html                  # 单文件浏览页：左侧按书架折叠，右侧读卡，可搜索
├── 关系网.html                # 单文件关系网（2D 力导向）
├── 关系网-3D.html             # 单文件关系网（3D 透视，可旋转缩放）
├── cards/
│   ├── 知识属性/
│   │   └── T-0002-non-rivalry-of-ideas.md
│   ├── 知识转换/
│   │   ├── T-0001-absorptive-capacity.md
│   │   └── M-0001-three-channels-of-public-science.md
│   ├── 创新激励/
│   ├── 产权与企业/
│   ├── 信息与合约/
│   └── 劳动与人力资本/
├── drafts/                   # 未定稿、待核来源的卡
├── rendered/                 # HTML / SVG 视觉副本，与 md 分开存放
└── .kcard/
    ├── meta.json             # 计数器、建库时间、schema 版本
    └── log.jsonl             # 审计流水（ingest / 改书架）
```

**卡片按书架分目录**，这是主要的检索路径：在资源管理器里点开 `cards/` 就能看到六个分类文件夹。

## 二、命名

- 卡片文件：`cards/<书架>/<id>-<slug>.md`，slug 全小写、连字符
- 视觉副本：`rendered/<id>.html`，与 md **不同目录**，避免卡片目录里混进 html/svg
- 草稿：`drafts/<slug>.md`；定稿后 `ingest` 会自动搬到对应书架并删掉草稿

## 三、书架

书架清单的权威定义在技能目录的 `taxonomy.json`：

```json
{"name": "知识转换", "key": "conversion", "order": 2,
 "desc": "知识从一处流到另一处的转化过程：吸收能力、技术转移、公共科学渠道",
 "keywords": ["吸收能力", "技术转移", "溢出", "扩散", "公共科学"]}
```

- `name` 同时是**目录名**，改动会移动目录，慎改。
- `order` 决定索引与浏览页的排序。
- `keywords` 只在**卡片没有 shelf 字段**时用于自动判定，不做强分类。

加一个书架（**推荐用命令，别手工改 JSON**）：

```bash
kcard.py taxonomy add 数字经济 --desc "平台、数据要素、算法与数字市场" \
  --keywords 平台经济 数据要素 算法 数字市场
```

它会把条目写进 `taxonomy.json`、建 `cards/数字经济/`、重建索引。旧卡不受影响，仍留在原书架。

改架名（目录、卡片 `shelf` 字段、清单一起改）：

```bash
kcard.py taxonomy rename 数字经济 数字与数据
```

改名会搬目录，所以**尽量一次定好名字**；如果只是嫌某个架装的东西杂，用 `shelf <id> <书架>` 逐张挪卡，别改架名。

**什么时候才该加架**：新卡片在六个现有书架里确实找不到"它主要回答的那个问题"时才加。判断标准不是"话题新不新"，而是"以后我会按哪个问题去找它"。空架多说明粒度太细，该合并。

## 四、索引

`INDEX.md` 由脚本生成，结构：

```
# 知识卡片库索引

共 8 张 · 5 个书架 · 更新于 2026-10-21

## 书架总览
| 书架 | 张数 | 理论 | 机制 | 效应 | 概念 | 一句话 |
| 知识属性 | 1 | 1 |  |  |  | 知识作为物品本身的性质… |

## 知识属性 · 1
> 知识作为物品本身的性质：非竞争性、排他性、可编码与隐性、复制成本
| id | 名称 | 英文 | 形态 | 证据 | 标签 | 来源数 |

## 知识转换 · 3
...

## 标签
知识(3) 创新(3) 增长(1)
```

`catalog.json` 是给脚本和 agent 读的扁平结构，每张卡都带 `shelf` 与归一化串（用于查重）。

`浏览.html`、`关系网.html`、`关系网-3D.html` 都是单文件页面，数据内嵌，可以直接双击打开或发给别人；`reindex` 会一起重建，`browse` / `graph` 可单独重建。

关系网只读 `relations`：卡片没挂边就不会出现，`doctor` 的孤立卡检查是它的上游。两个网共用一套引擎（`assets/graph.js` + `assets/graph.css`），区别只在投影方式；页面骨架由 `scripts/kcard.py` 的 `write_graph_html()` 拼出来，样式与脚本都从 `assets/` 读，改版式改那三个文件即可。

## 五、维护节奏

| 频率 | 动作 | 命令 |
| --- | --- | --- |
| 每次收录后 | 重建索引（`ingest` 已自动做一次） | `reindex` |
| 每周 | 体检：缺书架、断链、近重复、孤立卡 | `doctor` |
| 每月 | 合并近重复、给孤立卡补链接、复核放错书架的卡 | `doctor` + `shelf` |
| 每季度 | 挑 5 张卡重写"关联与争议" | 手动 |

## 六、备份

库是纯文本 + JSON，直接 git 或网盘同步即可。建议：

```bash
cd "D:/知识卡片库" && git init && git add -A && git commit -m "init"
```

不要只依赖单一位置。卡片库的价值随时间增长，丢失成本高于建库成本。

## 七、迁移

换机器：拷整个目录，设 `KCARD_HOME` 指向新路径即可，无需改任何卡片内的字段。卡片之间只用 `id` 互链，不用路径，所以迁移安全。

**从旧的扁平结构升级**（`cards/*.md` 全部堆在根目录）：

1. 跑 `kcard.py doctor`，看 `legacy_flat` / `missing_shelf` 两个计数。
2. 逐张定书架：`kcard.py shelf T-0003 产权与企业`（会自动建目录、移动文件、改 frontmatter）。
3. 把散落在 `cards/` 里的 html/svg 挪到 `rendered/`。
4. `kcard.py reindex`，`doctor` 应清零。

扁平目录仍被支持（`load_all` 递归读取），所以迁移可以分批做，不会读不到卡。

## 八、与阅读成果目录的关系

- **库内是唯一可编辑版本**
- 阅读成果目录下的 `04_知识卡片/` 只放报告与 HTML 副本
- 若两处都有 md，明确以库内为准，副本加一行 `> 本文件为副本，以库内 <id> 为准`
