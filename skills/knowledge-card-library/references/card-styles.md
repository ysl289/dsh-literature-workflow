# 卡片版式与视觉规范

> **这份是渲染器规格，不是写卡指南。** 写卡时只需要读第三节「章节的自动排版」——它告诉你正文写成什么样，卡片就会排成什么样。其余各节在改渲染器、或要手写 `edition:` 覆盖时再查。

五种版式，五种构图。**不要所有卡套同一个模子**——这是这套规范存在的唯一理由。

渲染器：`scripts/render_card_single.py`。一张卡输出一本小册子：**封面页 + 内页**（内页按字数自动增高或分页，末尾固定收「关系与出处」）。

---

## 一、选版决策（默认跳过这一步）

**默认不写 `edition:`**，让渲染器自己判。下面这张决策表是渲染器的内部逻辑，不是写卡步骤——写卡时先想清内容，写完看它长成什么样，明显错了再手写覆盖。

```
这张卡是什么形状？
├─ 章节 ≥7 且含公式，术语与假设都多  → ledger（账簿）
├─ 类型是概念/效应，标题 ≤8 字        → poster（海报）
├─ 「机制」有 ≥4 个编号步骤           → band（横幅）
├─ 结构是「对照／对立／分叉」          → atlas（图册）
└─ 其余（成体系的理论）               → atelier（工坊，默认）
```

写卡时显式声明，别让渲染器猜：

```yaml
edition: band        # atelier | band | poster | atlas | ledger
motif: fork          # gate | copy | fork | ladder | loop | stack | contrast | flow
origin_country: 美国  # 决定徽记与配色
style:               # 可选：覆盖配色（要能说出理由）
  cover: "#4a2f1d"
  accent: "#12705f"
```

兼容：旧字段 `cover_layout: side|band|center` 会映射到 `atelier|band|poster`。

## 二、五种版式的规格

页面统一 **1080 × 1500px**（A4 比例，屏幕上看像一本摊开的书），内页会随内容长高，绝不截断。

### `atelier` 工坊

```
┌───────────┬─────────────────────────┐
│  徽记      │  机制母题 · 闸门          │
│           │                         │
│           │      （母题水印）         │
│  编号·书架 │                         │
│  标题 88px │                         │
│  英文名    │                         │
│  ──────   │  ┌─────────────────┐    │
│  命题      │  │ 本册目录          │    │
│  作者      │  │ 01 …  02 …      │    │
└───────────┴─────────────────────────┘
```

- 左栏 39% 实色（`cover`），文字反白；右栏纸色，母题作 13% 石墨水印。
- 标题 88px，行距 1.1，`text-wrap: balance` 自动断行。
- 内页：双栏，栏间竖线；章节标题带下划线。

### `band` 横幅

```
┌─────────────────────────────────────┐
│ 编号·书架·母题              徽记      │
│                                     │
│           （母题，右下）              │
│  标题 68px                          │
│  英文名 / 作者                        │
├─────────────────────────────────────┤
│  命题 30px                          │
│                                     │
│  书架 │ 形态 │ 母题 │ 徽记    目录    │
└─────────────────────────────────────┘
```

- 横带高度自适应（约 390px），下沿是一条硬边。
- 标题压在带内左下，`max-width: 700px`；母题在右下、被带边裁切一点，才有印刷感。
- 命题 30px 居中于下半页的空白带里，底部信息条与目录对齐。

### `poster` 海报

```
┌─────────────────────────────────────┐
│              （母题）                │
│              编号·书架                │
│         标题 92px（居中）             │
│           英文名（强调色）             │
│   ── 作者 ──────────────── 母题 ──    │
│         命题（居中，30px）            │
│         目录（440px 窄栏）            │
│              徽记                    │
└─────────────────────────────────────┘
```

- 单栏正文，`max-width: 640px` 居中，行宽 28–32 字。
- 章节标题居中，两侧各一条 26px 短线。
- 留白最大，适合一句话就能说清的概念。

### `atlas` 图册

- 整册深色（纸＝封面色），正文反白，行线用 16% 白。
- 60px 网格底纹，母题放大到 640px 作半透明底图。
- 标题左下、巨大；目录压在底部。适合「对照／对立」这类需要压住场面的结构。

### `ledger` 账簿

```
┌─────────────────────────────────────┐
│ 编号·书架·形态 ═══════════ 作者       │  ← 双线页眉
│  （母题）  标题 64px                 │
│            英文名 / 母题              │
├──────────────────┬──────────────────┤
│ 命题              │  本册目录         │
│ ┌ 台账 ─────────┐ │                  │
│ │ 编号 T-0003   │ │                  │
│ │ 形态 theory   │ │                  │
│ │ 书架 产权与企业│ │                  │
│ │ 母题 无母题   │ │                  │
│ │ 徽记 无明确提出者│ │                │
│ │ 作者 GHM(1986)│ │                  │
│ └───────────────┘ │                  │
└──────────────────┴──────────────────┘
```

- 封面带**台账表**：编号／形态／书架／母题／徽记／作者，六行细线。
- 内页双栏、章节标题带上线，编号悬挂在正文外。
- 信息密度最高，适合假设多、术语多的卡。

## 三、章节的自动排版

渲染器不看章节名，只看**内容形态**：

| 内容形态 | 排成什么 | 写法 |
| --- | --- | --- |
| `1. 2. 3.` 编号列表 | **链条**：圆形编号 + 竖线串联 | `1. 合约没写清的地方，事后只能重新谈` |
| `- **术语**：解释` | **两列对照表** | `- **剩余控制权**：合约未明确之处，谁有权决定资产怎么用` |
| `- 甲：乙`（短键，≤16 字） | **两列对照表** | 只在「形式化／关键概念／关联与争议／边界与误用／前提假设」这几节生效 |
| `- 条目` | **悬挂列表**：短横线标记 | `- 知识不是自由品：……` |
| `$$…$$` | **通栏公式带**：上下双线、浅底 | 必须跟符号表 |
| `> 引文` | **引文块**：竖线 + 首字下沉；`虚构类比` 那行自动变成等宽题注 | `> 虚构类比，非论文原例。` |

> **`>` 只用来引原文或引虚构例子，不要用来自注。** 引文块带首字下沉，一个中文字被放大四倍会直接糊成一块图。自己的批注（"这个式子是重构，不是原式"之类）写成普通段落，前面加 `**注**` 即可。
| 其余 | 段落，两端对齐 | — |

**含公式的章节会自动变成通栏块**，把它前面的分栏流截断——所以公式放在中间是安全的，不会破版。

## 四、内容密度红线

- 单卡正文 **600–2200 字**。低于 600 说明这张卡还没写完；高于 2200 大概率不止一个理念，拆。
- 每个列表 3–6 条。第 7 条开始没人看。
- 一章不超过 3 段。超过就在段间加一个列表或一个编号步骤。
- 允许留白。渲染器会让内页随内容增高，**不要为了填满而注水**。

---

## 五、文案语气

**有趣不等于轻浮。** 目标是「能拿去讲」，不是「能拿去发朋友圈」。

- 用具体名词和数字，不用「非常重要」「意义重大」。
- 比喻必须能对上机制的关键环节；比喻对不上，就是装饰。
- 允许一句调侃，不允许通篇玩梗。
- 不确定的地方写「待核」「作者未说明」，不用模糊措辞蒙过去。

| 场景 | ✗ | ✓ |
| --- | --- | --- |
| 吸收能力 | 吸收能力超级重要！ | 别人家的论文，你得先自己写过论文才看得懂 |
| 非竞争性 | 知识是无穷的宝藏 | 我用不等于你用不了——这是知识区别于机器的关键 |
| 挤出效应 | 政府花钱害死人 | 政府多修一条路，可能只是让原本要修的那条不修了 |

## 六、导出

```bash
python scripts/render_card_single.py T-0001              # → rendered/T-0001.html
python scripts/render_card_single.py T-0001 --edition poster
python scripts/render_card_single.py --all               # 全库重出
```

- 单文件 HTML，字体与 KaTeX 走 CDN，**离线也能看**（数学公式会退化成 LaTeX 源码，不影响阅读）。
- 需要 PNG：浏览器整页截图；`@media print` 已设 A4、每页独立分页，可直接「打印为 PDF」。
- 不强制安装 Playwright——装不上就只交付 HTML，别为了导出图卡住流程。

---

## 七、可访问性

- 正文与背景对比度 ≥ 4.5:1；深色版式（`atlas`）上不要用低饱和强调色。
- 不靠颜色单独传达信息（关系类型同时有文字标签）。
- 字号下限 12px（仅限编号、题注这类附属信息）。
