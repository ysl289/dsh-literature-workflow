# 知识卡片设计信条

这份文件是**写卡时的设计指令**，不是事后点评。卡片好不好看，八成在写卡那一刻就决定了——渲染器只负责把已经想清楚的东西排出来。它救不了一张没有命题、没有母题、章节乱堆的卡。

每条规则都写着「为什么」。不知道原因的规则，下次一定会被违反。

---

## 零、先分清三件事

一张卡的美来自三层，缺一层就会塌：

| 层 | 谁决定 | 塌了会怎样 |
| --- | --- | --- |
| **命题** | 写卡时的一句话 | 读完不知道这张卡主张什么，再漂亮也是空壳 |
| **结构** | 章节的取舍与顺序 | 七节平铺，像词典条目，翻两张就腻 |
| **装饰** | 母题、徽记、配色、版式 | 每张都长一样，或者装饰跟理论无关 |

**判断标准只有一条**：把两张不同主题的卡并排放在桌上，如果除了文字之外看不出区别，就是模板；如果一眼能看出「这本讲闸门、那本讲复制」，才算成立。

## 一、一个例子，再上讲台

卡的第一节必须是**一个例子**：一个具体场景，谁、在什么处境、遇到什么，三到五句，**不出现任何术语**。把场景说完就停，不要加总结句。

判据只有一条：**把这一节单独发给一个没读过这篇论文的同学，他能不能复述出这个理论在说什么事。**

写不出来，说明你还没有真正理解这个理论，只是记住了它的术语。这时候别往下写——回去重读第 9 项。

「一个例子」不是故事。故事是虚构类比（"想象一个村庄……"），人话是**真实的、可核对的应用场景**（"一家做动力电池的公司，研发部门二十个人……"）。前者提供情绪，后者提供理解。

紧接着才是**命题**——一句能独立站住的话：

- 长度：**24–46 字**。短于 24 字通常太笼统（「知识很重要」），长于 46 字说明你还没想清。
- 句式：**「A 通过 B 导致 C」**或**「在 X 条件下，Y 不成立」**。要有一个转折或一个条件，否则就是废话。
- 命题允许自己断行：md 里写两行，页面上就是两行。别让渲染器替你断在词中间。

对照：

| ✗ 不能当命题 | ✓ 可以当命题 |
| --- | --- |
| 吸收能力是创新研究中的重要概念 | 企业自身的研究能力，决定它能从外部科学知识里吸收多少 |
| 产权影响企业边界 | 一体化减少敲竹杠，同时削弱被收购方的投资激励——最优边界是两者的平衡点 |
| 知识具有非竞争性 | 我用着不影响你用——这是知识区别于机器和土地的根本 |

## 二、结构跟内容，不跟模板

**章节由这个理论自己的形状决定。** 同一个标题在不同卡里可以有不同含义，同一张卡也不需要七节齐全。

### 章节顺序即叙事

按这个顺序想，然后**删掉不需要的**：

```
一个例子 → 命题 → 机制 → 形式化 → 用数字看 → 可检验含义 → 边界与误用 → 前提假设 → 在文献中的位置 → 关联与争议
```

**这个顺序是"一个没读过的人怎么才能懂"的顺序，不是"这个理论有哪些属性"的顺序。** 两者差别很大：

| 条目顺序（错） | 理解顺序（对） |
| --- | --- |
| 出处 → 前提 → 机制 → 形式化 → 概念 → 边界 | 场景 → 一句话 → 为什么 → 长什么样 → 数字 → 数据里怎么认 → 什么时候不成立 |

出现下面任一症状，就是顺序错了，回去重排：

1. 正文第一节是引文或文献出处；
2. 「可检验含义」排在「机制」前面——读者还不知道机制是什么，先看到回归设定；
3. 开头三句里出现了未定义的符号（$z$、$A$、交互项）。

- **出处不进正文**：写进 frontmatter 的 `first_source`，渲染时落页脚。一张纸翻开第一页是参考文献，是最典型的"看不懂"。
- **机制**：从 A 到 B 怎么发生。**写成编号步骤**（`1. 2. 3.`），渲染器会排成链条；写成整段散文，链条就没了，只能排成普通段落。每一步后面补一句「断在这里会怎样」，链条才有信息。
- **形式化**：有能写成关系的量才写。公式必须配符号表（`- $A$：……`），只给一行公式等于没写。
- **用数字看**：有公式就该有数字。参数写清、数字给出、结论一句话。读者自己算一遍，比读十行解释更信。
- **可检验含义**：这句话放进数据会长什么样——什么方向、什么交互、什么反事实。**写不出这一节，这张卡就只能当谈资。**
- **边界与误用**：什么时候不成立（理论边界），和最常见的用错方式（误读）。两者分开写，别和「谁改过」混在一起——一个是条件，一个是错误，用法完全不同。
- **关联与争议**：用 `**谁改过／主要批评**：……` 的格式，渲染器会排成对照表；写成整段，就只是段落。

### 什么时候该拆卡

- 标题里出现「与／及／和」连接两个理论 → 拆成两张，用 `relations` 互链。
- 一张卡出现两个独立的「机制」小节 → 拆。
- 单卡正文超过 2200 字 → 大概率不止一个理念。

**反例**：为了凑齐七节，把「读法」和「故事」硬塞进一页。理论条目不需要故事页——那是学习卡片的事。

### 能画成图的，别只写公式

公式证明你会写符号，图证明你懂机制。两者都在时，图优先。

一张合格的机制图只要满足一条：**把图单独拿给人看，他能说出"谁影响谁、往哪个方向、在什么条件下反转"。**

- 比较静态最值得画：一个量随另一个量怎么变，画三条线（不同参数）就够了，比一张符号表快十倍。
- 图上必须标出**对照**：同样的横轴增量，两条线抬升差多少。那才是"互补／替代"的证据。
- 不要画装饰性的示意图（圆圈箭头表示"循环"之类）。说不清机制，就不画。

**反例**：一页放一个巨大的公式带，公式下面四行符号表，读者看完还是不知道这个理论预测什么。

## 三、母题：装饰必须有出处

封面的大图形是这张卡的**机制形状**，不是插图。

八个母题不是菜单，是**给还没想清楚的卡临时用的分类**。优先级：

1. **`cards/<slug>.svg`** —— 这张卡专属的图形（能自己画就自己画，最有辨识度）
2. **`motif:`** 八个标准母题之一
3. **`origin_country`** 的徽记（提不出机制形状时的兜底）
4. 中性闸门（都判断不出）

| 母题 | 形状 | 什么时候用 |
| --- | --- | --- |
| `gate` 闸门 | 点穿过两道竖线，出来变成实心块 | 有门槛、要过滤、要吸收、要通过某条件才生效 |
| `copy` 复制 | 一份原样不动，旁边多出两份 | 非竞争性、复制成本、规模报酬 |
| `fork` 分叉 | 一个源分出多条通道 | 多渠道、多路径、分流、替代 |
| `ladder` 阶梯 | 逐级上升，台阶越来越窄 | 边际递减、分层、逐级筛选 |
| `loop` 回路 | 自我强化 | 正反馈、路径依赖、累积因果 |
| `stack` 堆叠 | 层层累积 | 存量、人力资本积累、知识叠加 |
| `contrast` 对照 | 两种情形并置 | 一体化 vs 非一体化、强保护 vs 弱保护 |
| `flow` 流转 | 单向传导，逐段变细 | 传导、损耗、溢出、衰减 |

**判据**：把封面图形单独拿给人看，他能说出「这是在讲门槛／复制／分叉」，才算成立。

**反例**：给「吸收能力」配埃菲尔铁塔。好看，但跟理论没关系。
**反例**：把八个母题当成"风格选项"每张挑一个轮着用。那还是模板，只是模板从 1 套变成 8 套。

## 四、配色从出身来，不从心情来

颜色由 `origin_country` 决定，取不到再按 `school` 映射，都没有才用默认：

| 出身 | 主色 | 气质 |
| --- | --- | --- |
| 美国（实证／期刊传统） | 深海军蓝 + 砖红 | 无衬线标题、严格细线、点阵底纹 |
| 法国（理论传统） | 藏青 + 酒红 | 高对比衬线、大留白、罗马数字 |
| 德国（体系／表格） | 近黑 + 金黄 + 砖红 | 无衬线、粗线、网格底纹 |
| 英国（古典政治经济学） | 深蓝 + 绛红 | 衬线、双线、横线纸底纹 |
| 中国 | 朱红 + 金 | 宋体标题、中文数字、点阵 |
| 奥地利 | 深红 | 衬线、罗马数字、无底纹 |

**什么时候可以用 `style:` 覆盖**：这张卡的机制有一种压倒性的颜色隐喻（例如「闸门」用墨绿），并且你说得出理由。说理由的方式是写进 `style:` 并在卡里留一句注释——不是随手换个好看的色。

**不要**：整库统一一套配色。翻十张全一个色，读者会认为这是同一个模板灌出来的。

## 五、五种版式＝五种构图

版式不是皮肤，是**构图**：标题放哪、分几栏、章节标题长什么样、纸面是亮是暗，全都不一样。

| 版式 | 构图 | 适合 |
| --- | --- | --- |
| `atelier` 工坊 | 左 39% 深色竖栏放编号/标题/英文名/命题/作者；右栏目录贴底，母题作水印 | **成体系的理论卡**（默认） |
| `band` 横幅 | 顶部整幅深色横带，标题压在带内左下，母题在右下；带下是命题 + 底部信息条 | **机制、渠道、流程**类；正文有 4 步以上编号 |
| `poster` 海报 | 居中对称，巨大标题，窄栏正文（28–32 字），留白最大 | **单一概念、定义型**；标题 ≤ 8 字 |
| `atlas` 图册 | 整册深色，网格底纹，母题巨大半透明，正文反白 | **对照、对立、分叉**结构 |
| `ledger` 账簿 | 双线页眉，密排两栏，封面带台账表（编号/形态/书架/母题/徽记/作者） | **假设多、条目多、术语多**的卡 |

**怎么选**：默认**不写** `edition:`，让渲染器按下面顺序判：

1. 章节 ≥ 7 且含公式 → `ledger`
2. 类型是 concept/effect 且标题 ≤ 8 字 → `poster`
3. 「机制」一节有 ≥ 4 个编号步骤 → `band`
4. 正文出现「对照」或母题是 `contrast` → `atlas`
5. 其余 → `atelier`

**什么时候手写 `edition:`**：渲染器明显猜错了（例如一张讲对照的卡被排成了默认工坊）。手写是纠错，不是选择。

> 曾经的做法是"写卡前先从五种里挑一个"。那一步看着很合理，实际把注意力从"这个理论该怎么讲"挪到了"我该套哪个模子"，而且一旦挑定，内容会不自觉地往那个模子里长。**先写，写完看它长成什么样，再决定要不要纠正。**

**反模板的硬指标**：连续三张新卡用同一个版式，说明你在套模子，不是在按内容排。这时候回去看这三张卡的章节是不是也长得一样——通常是同一个毛病。

## 六、排版数值（有据可依，不靠手感）

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 正文字号 | 15–16px | 低于 15px 中文发虚 |
| 行距 | 1.72–1.85 | 中文比西文需要更松，但到 2.0 就散了 |
| 行宽 | 28–34 字 | 超过 40 字眼睛回行会丢行 |
| 标题与正文比 | 4–6 : 1 | 68px 标题配 15.5px 正文 |
| 英文名 | Title Case | `Absorptive Capacity`，不要全大写，字号小时也别靠 `text-transform` 撑气势 |
| 章节标题 | 11px / 字距 .26em / 强调色 | 它是指路牌，不是标题 |

## 七、不要做的事

1. **不要 eyebrow。** 标题上方那种「小号＋大写字距＋带框」的标签，是 AI 生成感的第一来源。标题本身就够了。
2. **不要在封面放定义。** 封面只承担：编号 / 标题 / 英文名 / 命题 / 作者 / 目录。定义、公式、提问全部进内页。
3. **不要为凑整页塞内容。** 一页一个焦点；页数随内容增减。
4. **不要把每节都写成三段。** 该用列表的地方写列表，该用编号步骤的地方写编号步骤——渲染器按内容形态排版，你写成什么样，它就长什么样。
5. **不要用形容词代替机制。**「深刻揭示了」「极其重要」这类词一出现，这段就没信息了。
6. **不要用 `>` 写自注。** 引文块带首字下沉，单个中文字被放大四倍会糊成一块图。`>` 只用于引原文或引虚构例子；自己的批注写成普通段落，前面加 `**注**`。

## 八、交付前自检七问

1. **只看「一个例子」这一节，一个没读过这篇论文的人能不能复述出这个理论在说什么事？**
2. 从上往下读，有没有哪一处是"读者还不具备理解它的前提"？第一次出现这种地方，就是顺序错了。
3. 只看那句命题，能不能说出这张卡主张什么？
4. 这句话放进数据里会看到什么？能不能直接翻译成一个回归设定或一个可观测差异？
5. 把封面图形单独拿出来，能不能说出它在讲什么机制？
6. 把这张卡和库里另一张并排，能不能一眼看出两本不一样？
7. 有没有哪一节删掉之后，这张卡反而更清楚？

七问全过，再 `ingest`。**第 1 问不过就别收**——那张卡对别人是零信息，对三个月后的你自己也是零信息。第 4 问答不出来，说明它只到了"知道"，没到"能用"。
