# 卡片规范

## 一、什么算"一个经济理念"

进库的单元必须是**可命名的经济学主张**，而不是任何读起来有道理的话。按下面四类收，其余一律不收。

| 类型 | code | 说明 | 例子 |
| --- | --- | --- | --- |
| 理论 | `T` | 有明确提出者、有机制陈述、可被检验或反驳 | 吸收能力、知识的非竞争性、搜寻匹配 |
| 机制 | `M` | 说明"为什么 A 导致 B"的中间过程，通常依附于某理论 | 挤出机制、人才承载知识的排他化、竞争性替代 |
| 效应 | `E` | 有方向性的经验规律或偏效应 | 干中学效应、规模报酬递增、羊群效应 |
| 概念 | `C` | 分析用的界定性工具，本身不构成因果主张 | 机会成本、外部性、自然失业率 |

**不收的东西**：

- 数据描述、样本量、变量构造（这些属于精读笔记里的数据与变量记录，不是理念）
- 纯计量技术（DID、IV 本身不是经济学理念；但"选择性偏误""排除限制"作为识别概念可以收）
- 作者的结论句，如果它只是"我们发现 X 显著"——没有机制主张就不成卡
- 政策口号、时评判断

**一条实用判据**：能不能用"如果……那么……因为……"造一个句子？造不出"因为"，说明它还不是理念。

## 一之二、两个分类维度

上面的四类只是**形态**（`type`），决定编号前缀与版式。卡片还有**书架**（`shelf`），决定它在库里放在哪个目录、索引里归哪一组。

| 维度 | 字段 | 是否互斥 | 作用 |
| --- | --- | --- | --- |
| 形态 | `type` | 互斥 | id 前缀 T/M/E/C、版式、索引列 |
| 书架 | `shelf` | 互斥 | 目录位置、索引分组、浏览页分组 |
| 标签 | `tags` | 多值 | 交叉检索 |

书架取值与判定规则见 `SKILL.md` 的「分类」一节，权威清单见技能根目录 `taxonomy.json`。

**一卡只归一个书架。** 两个书架都沾边时，问"这张卡主要回答哪个问题"，按主要问题归架，另一侧用 `relations` 连过去。

## 二、命名规则

- **主名**：中文通用译名，不带"理论/假说/模型"后缀（"吸收能力"，不写"吸收能力理论"）。后缀只在正文标题里出现。
- **英文名**：学界通行写法，首字母大写（`Absorptive Capacity`）。
- **别名**：收常见别译、缩写、学者名版本、以及你所在领域的习惯叫法。别名是查重的第一道防线，值得多花 30 秒。
- **slug**：小写英文连字符，用于文件名与链接（`absorptive-capacity`）。

## 三、id 规则

`类型码-四位序号`，如 `T-0001`、`M-0007`、`E-0012`、`C-0003`。

- 序号全局按类型自增，**永不复用**。删卡不回收编号，避免历史笔记里的引用指向错误对象。
- 文件名：`cards/<书架>/<id>-<slug>.md`，如 `cards/知识转换/T-0001-absorptive-capacity.md`。
- id 由 `ingest` 分配：卡片里没写 id 就自动取下一个号；写了 id 则校验格式、前缀与形态一致、未被占用。

## 四、frontmatter 字段

```yaml
---
id: T-0001
type: theory                  # theory | mechanism | effect | concept
shelf: 知识转换               # 书架：知识属性 / 知识转换 / 创新激励 / 产权与企业 / 信息与合约 / 劳动与人力资本
title_zh: 吸收能力
title_en: Absorptive Capacity
aliases:
  - 企业吸收能力
  - 吸收能力理论
slug: absorptive-capacity
status: verified              # draft | verified | disputed
confidence: high              # high | medium | low（证据强度，不是你的把握）
school: 演化经济学与创新研究
origin_country: 美国          # 提出者所属国家，决定徽记与配色
motif: gate                   # 机制母题：gate/copy/fork/ladder/loop/stack/contrast/flow
edition: atelier              # 构图：atelier/band/poster/atlas/ledger（见 design-doctrine 第五节）
style:                        # 可选：这张卡专属的皮肤，覆盖出身预设（要能说出理由）
  cover: "#0f3a34"
  accent: "#c9622f"
  display_font: '"Noto Serif SC",serif'
  leading: "1.82"
era: "1990-"
authors:
  - Cohen, W. M.
  - Levinthal, D. A.
first_source:
  citation: Cohen, W. M., & Levinthal, D. A. (1990). Absorptive capacity: A new perspective on learning and innovation. Administrative Science Quarterly, 35(1), 128-152.
  locator: 第 128-129 页
sources:
  - citation: Arora et al. (2023), NBER WP 31899
    locator: PDF 第 10 页脚注 8-9
    role: 引用            # 提出 | 引用 | 检验 | 反驳 | 扩展
relations:
  - type: 前置            # 上位 | 下位 | 对立 | 互补 | 前置 | 应用于
    target: T-0002
    note: 吸收能力是解释"公共知识为何需内部研究"的前提
tags:
  - 创新
  - 企业理论
created: 2026-10-20
updated: 2026-10-20
---
```

字段纪律：

- `shelf` 必填且只能取 `taxonomy.json` 里登记的书架名；缺了 `doctor` 会报 `missing_shelf`。
- `confidence` 指**文献证据的强度**：多篇独立实证支持 = high；单一研究或纯理论 = medium；有争议或已被推翻 = low（配 `status: disputed`）。
- `first_source` 必须是提出该理念的原始文献，不是二手转述。找不到原文就写 `待核` 并在 `status` 标 `draft`。
- `locator` 不允许为空。写不到页码就写章节或表图编号。
- `sources` 是"这个理念被哪些文献用到"的流水账，每读一篇相关文献就追加一条——这是卡片库产生复利的地方。
- `refs` / `refs_drop` 是面板「文献映射」写的两个字段，**手写卡片时不用填**。映射默认从 `first_source` 与 `sources` 自动推断；`refs` 只用于手工补挂或改角色，`refs_drop` 用于把某篇文献从自动推断里剔除（`sources` 里的那条引用不动，只是不再计入映射）。文献标识是「第一作者姓 + 年份」（如 `Cohen_1990`），与阅读成果目录的 `<作者>_<年份>` 命名对齐。
- `motif` 决定封面图形，**写卡时就要定**；判断不出就留空，别硬凑一个。`edition` 默认不写，交给渲染器按内容判，只在它猜错时手写覆盖。
- `origin_country` 只写提出者所属国家。**判断不出就留空**，不要为了配色好看编一个。

## 四之二、动笔前必须想清的三件事

| 要定什么 | 回答的问题 | 判断不出时 |
| --- | --- | --- |
| 命题（正文第一节） | 这张卡主张什么？24–46 字 | 说明还没想清，回去读第 9 项 |
| 可检验含义（正文一节） | 这句话放进数据会长什么样？ | 说明它还没到"能用"，先别收 |
| `motif` | 这个理论的机制是什么形状？ | 留空，用 `origin_country` 的徽记兜底 |

`edition`（版式）不在这三件里：默认交给渲染器按内容判，只在它明显猜错时手写。理由见 `design-doctrine.md` 第五节。

母题与正文不一致是最常见的难看原因：例如母题写 `copy`（复制），正文讲的却是门槛与筛选，封面图形就在说另一件事。


## 五、正文骨架

一张卡是一个**经济理论条目**。章节按内容取舍，不套固定清单；渲染器与浏览页按 `##` 顺序排版，写什么排什么。

下面是**写法参考**，不是脚本生成的模板——正文由模型一次写完，`ingest` 只检查完整性（至少两个 `##` 章节、正文 ≥ 80 字、出处有 locator、有 title_en），不改写一个字。

```markdown
## 一个例子

一个具体场景：谁、在什么处境下、遇到什么。三到五句，**不出现任何术语**。

把场景说完就停。不要加"这就是为什么……"这类总结句，也不要加粗——它们是模板腔最明显的痕迹。

（这一节必须排在最前面。判据：单独发给一个没读过这篇论文的同学，他能不能复述出这个理论在说什么事。）

## 核心命题

一句话说清这个理论主张什么。md 里可以自己断行——写两行，页面上就是两行。

## 机制

从 A 到 B 是怎么发生的。写成 `1. 2. 3.` 编号步骤，渲染器会排成链条。

## 形式化

$$A = z \cdot f(Z)$$

- $A$：符号含义
- $z$：符号含义

没有可形式化的量就整节不写，不要硬套。

## 用数字看

一个能自己算的小例子。参数写清、数字给出、结论一句话。

## 可检验含义

这句话放进数据会长什么样：预期什么方向、什么交互项、什么反事实对照。
写不出这一节，说明这张卡只到了"知道"，没到"能用"。

## 边界与误用

- **什么时候不成立**：理论成立的边界条件
- **常见误读**：最常见的用错方式，以及错在哪

## 前提假设

- 在什么条件下这个理论成立
- 哪些条件被明确写出来，哪些是隐含的

## 关键概念

- **术语**：它在这个理论里的确切所指

（术语在机制段里已经解释过，就删掉这一节。）

## 在文献中的位置

所读论文怎么用它、用在哪一步、替代了什么解释。只写"某文用过它"等于没写。

## 关联与争议

- 谁改过（后续文献的拆分或扩展）
- 与相近理论的区别
```

**出处不进正文**，写进 frontmatter 的 `first_source`，渲染时落页脚。读者翻开正文第一眼看到的应该是"讲了什么事"，不是一条英文引文。

**顺序不是随便排的。** 上表的顺序是"一个没读过这篇论文的人怎么才能懂"的顺序，不是"这个理论有哪些属性"的顺序。把 `## 可检验含义` 挪到 `## 机制` 前面，读者就会在还不知道机制是什么的时候先看到回归设定——这是最常见的"看不懂"来源。判据：从上往下读，第一次出现"读者还不具备理解它的前提"的地方，就是顺序错了。

**不要写**：故事、自测三问这类学习卡片板块。「一个例子」不是故事——故事是虚构类比，人话是**真实的、可核对的应用场景**。

**注意**：「常见误读」属于「边界与误用」，不属于「关联与争议」。前者讲"怎么用错"，后者讲"学界怎么改"。混在一起，读者分不清哪条是理论进展、哪条是使用禁忌。

章节名可以按理论类型改：博弈论可以加"均衡"，制度经济学可以加"制度环境"，不需要统一。

### 写法直接影响排版

渲染器按**内容形态**排版，所以下面四种写法不是风格偏好，是排版指令：

| 你写成 | 卡片上会变成 |
| --- | --- |
| `1. 2. 3.` 编号列表 | 圆形编号 + 竖线串联的**链条** |
| `- **术语**：解释` | 两列**对照表**（术语在左，解释在右） |
| `$$…$$` + `- $符号$：含义` | 通栏**公式带** + 符号表 |
| `> 引文`（首行写「虚构类比，非论文原例。」） | 竖线**引文块** + 等宽题注 + 首字下沉 |

同一节里混着写（三条带冒号、两条不带），渲染器会退回成普通列表——想要对照表，就让整节都写成 `键：值`。


## 六、写作语气

**有趣不等于轻浮。** 目标是"能拿去讲"，不是"能拿去发朋友圈"。

- 用具体名词和数字，不用"非常重要""意义重大"。
- 比喻必须能对上机制的关键环节；比喻对不上，就是装饰。
- 允许一句调侃，不允许通篇玩梗。
- 不确定的地方用"待核""作者未说明"，不用模糊措辞蒙过去。
