# 知识卡片库

## 定位

卡片库不是摘抄本，而是一组**可复用的经济学理念**的最小单元。每张卡只回答一件事：这个理念说什么、为什么成立、什么时候不成立、怎么讲给别人听。

判断做得好不好，标准只有一条：三个月后你只读这张卡，能不能在讨论里把它用出来。

## 这个技能不建卡，只收卡

**卡片正文一律由模型整篇写出来，脚本不生成任何骨架、不提供"新建卡片"功能。**

原因很简单：写卡的是 AI，不是人。让脚本吐一个满是「待补」的模板，再让 AI 去填空，只会多一道搬运工序，还容易把模板的板式带进正文。

所以分工是：

| 谁 | 干什么 |
| --- | --- |
| 模型 | 判断值不值得收、查重、**把整张卡写完**（frontmatter + 正文一次成型） |
| 脚本 | 校验字段与正文是否完整、分配编号、按书架落位、重建索引与浏览页、体检 |

脚本的 `ingest` 是**入库闸门**，不是建卡向导：正文没写完、出处没定位、和库里已有卡重复，一律拒绝落盘（退出码 3）。

## 三条铁律

1. **一卡一理念。** 一张卡只承载一个可命名的理念。标题里用"与/及/和"连接两个理论的，拆成两张卡，再用 `relations` 互链。
2. **先查后写。** 动笔前必须跑 `kcard.py check`。命中已有卡片时默认不写新卡——重复卡片比没有卡片更有害，它会让库失去可信度。
3. **溯源到页。** 每张卡必须有 `first_source`，定位到页码、章节或表图编号。定位不了的内容不进库，宁可先记在草稿里。

## 库的位置

库根解析顺序：环境变量 `KCARD_HOME` > `DSH_CARDS_HOME` > 默认 `~/Desktop/知识卡片库`。目录结构见 [references/library-layout.md](references/library-layout.md)。

> 库根可用 `KCARD_HOME` / `DSH_CARDS_HOME` 覆盖；默认落在 `~/Desktop/知识卡片库`。

## 分类：形态 × 书架

卡片按**两个维度**分类，别混用：

| 维度 | 字段 | 取值 | 决定什么 |
| --- | --- | --- | --- |
| 形态 | `type` | theory / mechanism / effect / concept | id 前缀（T/M/E/C）、版式、索引里的列 |
| **书架** | `shelf` | 见下方六个 | **目录位置、索引分组、浏览页分组——这是主要检索维度** |

**书架是互斥的：一张卡只归一个书架。** 跨书架的关联用 `relations` 表达，不要复制卡片、也不要一卡多架。标签（`tags`）才是多值的，用来做交叉检索。

当前书架（权威清单在 `taxonomy.json`，含关键词，`kcard.py shelves` 可查实时分布）：

| 书架 | 装什么 |
| --- | --- |
| 知识属性 | 知识作为物品本身的性质：非竞争性、排他性、可编码与隐性、复制成本 |
| 知识转换 | 知识怎么流动与被吸收：吸收能力、技术转移、公共科学渠道、扩散与溢出 |
| 创新激励 | 为什么愿意创新、创新收益怎么分：专利、竞赛、先占、创新租金 |
| 产权与企业 | 企业为什么存在、边界画在哪：产权配置、剩余控制权、不完全合约 |
| 信息与合约 | 信息不对称导致的行为扭曲：道德风险、逆向选择、信号、委托代理 |
| 劳动与人力资本 | 劳动市场与人的能力积累：工资、技能、人力资本、搜寻匹配 |

**定书架的顺序**：先看这张卡回答的问题属于哪一类 → 对不上任何一条时，别硬塞，先问用户；确实需要一个新书架，就在 `taxonomy.json` 里加一条（名称、key、order、desc、keywords），再跑 `reindex`。

拿不准时让脚本先猜：`kcard.py check --title "..."` 会顺带返回 `shelf_suggestion`，按关键词打分给出建议书架与命中词，供你复核。**建议只是建议，最终书架要你自己判断后写进 frontmatter 或 `--shelf`。**

### 遇到现有书架装不下的新领域

按顺序走，别跳步：

1. **先试着放进现有书架。** 大多数"新领域"其实只是新话题。数据要素的规模报酬讲的是非竞争性 → 归「知识属性」；平台补贴讲的是激励设计 → 归「创新激励」。硬开新架会把六个架变成三十个，检索反而更难。
2. **确实装不下时，先问用户**，说清三件事：为什么现有六个都不合适、建议的架名、这个架以后大概装什么。书架是对整个库的结构性改动，名字要用户点头。
3. **同意后一条命令加架**（不要手工改 JSON、不要手工建目录）：

   ```bash
   python scripts/kcard.py taxonomy add 数字经济 \
     --desc "平台、数据要素、算法与数字市场" \
     --keywords 平台经济 数据要素 算法 数字市场
   ```

   它会写进 `taxonomy.json`、建 `cards/数字经济/`、重建索引。`--keywords` 决定以后同类卡片能否被自动判定命中。
4. **再收录那张卡**：`kcard.py ingest 卡片.md --shelf 数字经济`。
5. **老卡要跟着搬**：单张用 `kcard.py shelf T-0007 数字经济`；整个架改名用 `kcard.py taxonomy rename 数字经济 数字与数据`（目录、卡片字段、清单一起改）。

三条纪律：

- **一次只加一个架**，加之前先看 `kcard.py shelves` 的分布。空架多 = 粒度太细，该合并而不是再加。
- **按问题命名，≤12 字**（「数字经济」而不是「Jones and Tonetti 2020」）。名字定下就少改；要改走 `taxonomy rename`，别在资源管理器里拖目录。
- **拿不准就先收进「未归类」**：`--shelf 未归类`，等攒到两三张再决定要不要独立成架。别为了单张卡造一个永久书架。

一个必须知道的坑：**不给 `--shelf` 时，`ingest` 只在已有书架里挑**，它不会告诉你"这里缺个新架"——碰到全新领域，自动判定往往会把卡塞进某个"有点像"的旧架。所以新领域一定要显式 `--shelf`。

## 五个动作

| 动作 | 命令 | 作用 |
| --- | --- | --- |
| 查重 | `python scripts/kcard.py check --title "吸收能力"` | 返回 JSON 判定、候选卡片、书架建议 |
| 收录 | `python scripts/kcard.py ingest 卡片.md --shelf 知识转换` | 校验 + 编号 + 按书架落位 + 重建索引 |
| 归架 | `python scripts/kcard.py shelf T-0007 知识转换` | 改书架，同时移动文件、更新索引 |
| 管架 | `python scripts/kcard.py taxonomy add 数字经济 --desc "..."` | 新领域加书架；`rename` 改架名 |
| 索引 | `python scripts/kcard.py reindex` | 重建 `catalog.json`、`INDEX.md`、`浏览.html`、两张关系网 |
| 关系网 | `python scripts/kcard.py graph` | 只重建两张关系网：`关系网.html`（2D）与 `关系网-3D.html` |
| 体检 | `python scripts/kcard.py doctor` | 查重复 id、断链、缺字段、缺书架、骨架卡、坏 locator、近重复、孤立卡 |

## 关系网：两种投影

`reindex` 会同时生成两个单文件页面，都自带全部数据、可离线双击打开，左下角可互相切换：

| 文件 | 观感 | 适合 |
| --- | --- | --- |
| `关系网.html` | 平面力导向，同书架的卡聚成带虚线边的「领域」 | 看清拓扑：谁和谁连着、有几条链 |
| `关系网-3D.html` | 三维力导向 + 透视投影，近大远小 | 看清结构：哪个理论在中心、哪几条边是骨架 |

版式是「左读图控制台 / 中画布 / 右关系清单」，读图只靠三件事：

- **点 = 一张卡**：大小 = 关系条数，颜色 = 书架；外面一圈橙色虚线 = 还没挂关系（孤立卡）
- **线 = 一条关系**：**箭头指向被提到的那张卡**，颜色 = 关系类型（前置橙 / 应用于蓝 / 上位下位紫 / 互补绿 / 对立红）；实线 = 结构关系，虚线 = 并列关系（互补/对立/相关）
- **领域 = 一个书架**：同书架的卡被围成一片，上方标着书架名与张数

几条刻意的设计：

- 每条关系一根独立的线，两卡互指时是两根平行错开的线（如「A 应用于 B」＋「B 的前置是 A」），绝不合并——这正是要看的信息
- 右侧清单**按「对方那张卡」归并**，8 张卡之间只列 7 组；两张卡各自写了对方时标「双向声明」，并把两处理由并排给出
- 左栏点书架或关系类型 = **只看这一类**，Shift 点 = 叠加，「全显」复位；筛选只改可见性，**绝不重排**（方位不会因为点一下而全变）
- 选中某张卡时，与它无关的卡片、线条、地块一起退到背景，只留一跳邻居；右侧清单末尾若有卡片图，会给出「看这张卡」，点开就是那张 A4 卡
- 关系文字默认只在这张卡被指到/选中时出现；放大到 2.4 倍以上才全部显示
- 左栏底部「全屏」：图铺满整块屏幕并重新取景；「适应窗口」随时把全部卡片框回视野（不会把左边的卡留在视野外）
- 3D 版：拖空白处旋转、滚轮缩放，「自动旋转」默认关（转起来就没法读了）

**关系网只读 `relations` 字段**，所以卡片没挂关系就不会出现在网上——这也是 `doctor` 会报孤立卡的原因。

harness 的面板插件（`dsh-knowledge-cards`）里有「关系网」标签，点开直接内嵌这两张图，默认给平面版，可切 3D、可重新生成；被内嵌时页面会收掉自己的标题栏（面板顶上已有）。它调用的是同一个 `kcard.py graph`，所以面板里看到的和文件夹里的永远一致。

## 查重协议（本技能的核心）

脚本负责初筛，模型负责复核，两步都不能省。

| 判定 | 触发条件 | 动作 |
| --- | --- | --- |
| `duplicate` | 归一化标题 / 别名 / 英文名完全一致；或相似度 ≥ 0.92 且复核确认是同一理念 | **不写卡**。在既有卡的 `sources` 追加本次来源，`updated` 改今天 |
| `variant` | 同一理念的不同命名、不同表述、不同学者版本 | **不写新卡**。并入既有卡：新名字进 `aliases`，正文补一段"版本差异" |
| `related` | 相关但独立（上位 / 下位 / 对立 / 互补 / 前置） | 写新卡，并在双方 `relations` 互链 |
| `new` | 无命中 | 写新卡，然后 `ingest` |

细则、阈值算法和边界案例见 [references/dedup-protocol.md](references/dedup-protocol.md)。

**必须警惕的误合并**：逆向选择 ≠ 道德风险（同属信息不对称，机制不同）；规模经济 ≠ 范围经济；挤出效应 ≠ 替代效应。宁可判 `related` 也不要错并。

## 制卡流程

0. **定源**：明确输入。流水线入口取 `extract.json` 的 `economic_theories`；伴读入口取精读与研究笔记产物中「本文真正用到的理论」；也可以是用户直接给的文本。
1. **抽理念**：按 [references/card-spec.md](references/card-spec.md) 的"什么算一个经济理念"筛选，宁可少抽不要凑数。
2. **归一化命名**：中文主名 + 英文名 + 别名（含常见别译、缩写、学者名版本）。
3. **查重**：跑 `check`，拿到候选、分数与书架建议。
4. **定级**：按上表判四态。`duplicate` / `variant` 到此为止，不写卡。
5. **定形**（写卡前必须做完）：
   - **一个例子**：一个具体场景，3–5 句，**不出现任何术语**。把场景说完就停，不要加一句总结、不要加粗收口——那是模板腔。这一节决定"看完知不知道讲了什么"，**写不出来就别写这张卡**。判据：把它单独发给一个没读过这篇论文的同学，他能不能复述出这个理论在说什么事。
   - **命题**：一句话把这张卡的主张写出来，24–46 字，能独立站住。**md 里可以自己断行**，写两行页面上就是两行——别让渲染器替你断在词中间。
   - **可检验含义**：这句话放到数据里，会看到什么？写不出这一条，说明它只能当谈资，进不了你的实证设计。**这是理论卡最容易漏、也最值钱的一节。**
   - **母题**：这个理论的机制是什么形状？闸门／复制／分叉／阶梯／回路／堆叠／对照／流转。判断不出就留空，渲染器会用出身徽记兜底；能自己画 `cards/<slug>.svg` 更好。
   - **版式**：`edition:` 一般交给渲染器按内容判（看章节数、编号步骤数、有没有公式）。**只有它猜错时才手写**。别把"挑版式"当成写卡的第一步——先想清内容，构图是结果。
   - **出身**：`origin_country`（提出者所属）决定徽记与配色；判断不出就留空，不要编。
6. **写卡**：**一次写完**——frontmatter 填全（含 `shelf`、`edition`、`motif`），正文按内容组织章节。写成**理论条目**，章节由内容决定，见下节。不要留「待补」占位，脚本会拒绝收录。
7. **收录**：`ingest` 该文件。想先写在外面（比如阅读成果目录）也行，`ingest` 会把卡搬到对应书架，并清掉库内的临时稿。
8. **建链**：补 `relations`，至少给新卡挂一条边，避免孤岛；反向边也要补。
9. **索引**：`reindex`（`ingest` 已自动跑一次，改完 relations 再跑）。
10. **润色**：用 `humanizer-zh` 过一遍正文，按下一节的六条自查。**这一步不做，前面九步都白搭**——内容对、结构对、版式对，读起来还是像机器写的。
11. **出卡**：默认走 `render_sheet.py`，一张单栏长纸，无封面、无目录，输出 `rendered/<id>-sheet.html`。**这是给人读的那一版**，日常看它。
    需要打印或发人时再走 `render_card_single.py`，排成一本小册子（封面 + 分栏内页），输出 `rendered/<id>.html`；`--edition` 可强制版式。
    两条出口同一份 md，改内容不用改两遍。

## 写卡时的排版自觉

渲染器**按内容形态排版**，所以你写成什么样，卡就长什么样。这四条直接决定成品好不好看：

1. **「机制」写成编号步骤**（`1. 2. 3.`）→ 排成链条；写成整段散文 → 只能排成普通段落。**机制的价值往往不在"它有三步"，而在"它在哪一步断"**——每步后面补一句失效条件，链条才立得住。
2. **「形式化」必须配符号表**（`- $A$：……`）→ 排成两列对照表 + 通栏公式带；只给一行公式 → 那一节空得发慌。
3. **「边界与误用」用 `**谁改过／主要批评／常见误读**：……`** → 排成对照表；写成整段 → 只是段落。
4. **能画成图的，别只写公式**——一个量对另一个量的比较静态（几条曲线、一张对照），比符号表更快让人看懂机制。图要能说出机制，不能只是装饰。

细则与反例见 [references/card-styles.md](references/card-styles.md) 第三节（只看这一节就够）。


## 文风：出卡前必须过一遍

**写完正文，用 `humanizer-zh` 技能润色一遍再渲染。** 这个技能装在 `~/.agents/skills/humanizer-zh/`，31 条检查点，专门治中文的模板腔。

为什么这一步不能省：卡片最容易被读成"AI 生成的说明文"，而读者对这个极其敏感。版式再干净，一段「不仅……更是……」就能让人不想看下去。

卡片场景下命中率最高的六条，写完先自查：

| 毛病 | 典型写法 | 怎么办 |
| --- | --- | --- |
| 假对比（§1） | 「不是 X，而是 Y」 | 一节里最多一次；两部分都提供信息时才留 |
| 单句收尾（§2） | 段末一句加粗的短句收口 | 删掉。话说完就停 |
| 意义拔高（§13） | 「最关键的一点：」「值得注意的是」 | 删掉标签，直接说事 |
| 粗体装饰（§19） | 每段开头都加粗一个词组 | 只留跳读真正需要的 |
| 破折号当连接（§8） | 一段里两三个「——」 | 换句号、冒号或逗号 |
| 四字词排比（§29） | 「稳定可靠、快速响应、易于维护」 | 拆成具体说法 |

还有一条是卡片特有的：**栏目名不要用元指令。**「先说人话」这种名字本身就是 AI 腔——它在向读者解释我要干什么。用名词：「一个例子」「机制」「数字」「边界」。

判断标准不是"像不像人写的"，是**这段话有没有一个具体的人在说**。同一件事，写「这套方案运行稳定、响应快，也方便维护」，比「稳定可靠、快速响应、易于维护」多了一个人的判断。


## 卡片内容：理论条目

一张卡是一个经济理论条目，不是学习笔记。**章节按内容取舍，不套固定清单。**

常见章节（可增删、可改名）：

| 章节 | 写什么 | 是否常有 |
| --- | --- | --- |
| 一个例子 | 一个具体场景，不用术语，说完就停 | **必有，且必须排第一** |
| 核心命题 | 一句话说清这个理论主张什么 | 必有 |
| 机制 | 从 A 到 B 是怎么发生的 | 常有 |
| 形式化 | 有可写成关系的量才写；公式 + 符号表 | 条件性 |
| 用数字看 | 一个能自己算的小例子，把机制变成数字 | 有形式化就该有 |
| 可检验含义 | 放到数据里会看到什么：什么方向、什么交互、什么反事实 | **理论卡应有** |
| 边界与误用 | 什么时候不成立；最常见的用错方式 | 常有 |
| 前提假设 | 这个理论在什么条件下成立 | 常有 |
| 关键概念 | 术语与它在本文里的确切所指 | 术语多才写 |
| 在文献中的位置 | 所读论文怎么用它、用在哪一步 | 视情况，没话说就不写 |
| 关联与争议 | 谁改过、谁反对 | 常有 |

**出处不占正文章节。** 写进 frontmatter 的 `first_source`，渲染时自动落在页脚。读者翻开正文第一眼看到的应该是"讲了什么事"，不是一条英文引文。

**不要写**：故事、自测三问这类学习卡片板块——理论条目不需要。注意「一个例子」不是故事：故事是虚构类比，人话是**真实的、可核对的应用场景**。

### 叙述顺序：按理解顺序，不按条目顺序

同一批内容，顺序不同就是两张卡。**默认按"一个没读过这篇论文的人怎么才能懂"来排**，不按"这个理论有哪些属性"来排：

| 条目顺序（错） | 理解顺序（对） |
| --- | --- |
| 出处 → 前提 → 机制 → 形式化 → 概念 → 边界 | 场景 → 一句话 → 为什么 → 长什么样 → 数字 → 数据里怎么认 → 什么时候不成立 |

判据很简单：**把卡从上往下读一遍，第一次出现"读者还不具备理解它的前提"的地方，就是顺序错了。**
典型症状有三个，出现任何一个都要重排：

1. 正文第一节是引文或文献出处；
2. 「可检验含义」排在「机制」前面——读者还不知道机制是什么，先看到回归设定；
3. 开头三句里出现了未定义的符号（$z$、$A$、交互项）。

**"关键概念"与"机制"重复度最高**：如果概念在机制段里已经解释过，这一节就删掉，别为了凑节数留着。"在文献中的位置"同理——只写"某文用过它"等于没写，要写清用在哪一步、替代了什么解释。

渲染器与浏览页都按 `##` 章节顺序排版，写什么排什么。

## 设计信条

做卡之前先读 [references/design-doctrine.md](references/design-doctrine.md)。[references/card-styles.md](references/card-styles.md) 是渲染器规格，写卡时不用读，只在改渲染器或强制版式时查。核心四条：

1. **开头先给例子**——第一节永远是「一个例子」：一个具体场景，不用术语。**一张卡如果只有一节能留下，就留这一节。** 命题、公式、可检验含义都排在它后面；读者没被带进场景，后面写得多准都读不进去。
2. **结构跟内容，不跟模板**——章节由理论自己的形状决定；「机制」写成编号步骤，「边界与误用」写成 `**谁改过／常见误读**：……`，渲染器才知道该排成链条还是对照表。
3. **装饰必须有出处**——优先用这张卡自己的机制母题（`motif:`），其次用提出者国家的徽记，都判断不出才用中性闸门。**不为了好看挑图案。**
4. **构图是结果，不是选项**——`atelier / band / poster / atlas / ledger` 的标题位置、分栏、纸面明暗都不同。但版式应该从内容里长出来，而不是先挑一个再往里填。两张卡并排，应该一眼能看出「这本讲闸门、那本讲复制」。

### 反模板体检

写完先自查三条，有一条不过就回去改：

1. **七节齐全 + 每节三段** = 模板。库里已经这样了：23 张卡里「核心命题／在文献中的位置／关联与争议」21 张全齐，而「形式化」只有 9 张。章节全齐不是完整，是没取舍。
2. **这一节删掉，卡片会不会更清楚？** 会，就删。「关键概念」和「在文献中的位置」是最常该删的两节。
3. **把命题单独发给同学看**，他能不能复述出这张卡主张什么、什么时候不成立？不能，就是还没写清。

## 排版规则

- **英文名一律 Title Case**（`Absorptive Capacity`），不要全大写，也不要全小写。字号小时也不要靠 `text-transform` 撑气势。
- 中文正文行宽控制在 28–34 字，超过就分栏或缩窄容器。
- 一页只放一个焦点；页数随内容增减，不要为凑整页塞内容。
- 封面只承担封面：编号 / 标题 / 英文名 / 命题 / 作者 / 目录。定义、公式、提问都放到内页。
- **封面地标（`marks.py`）**：装饰要有出处，不随手挑图案。
  1. 有明确提出者 → 用提出者所属国家的地标线稿（`origin_country` 字段）
  2. 没有明确提出者 → 按学派归属（`school` 字段自动映射）
  3. 两者都判断不出 → 用中性符号「闸门」，不硬凑
  版权页同步标注"来源：美国 · 提出者所属"或"来源：无明确提出者"。
- **不要 eyebrow**：标题上方那种「小号＋大写字距＋带框」的标签，是 AI 生成感的第一来源。


## 质量红线

- **不编造**：作者、年份、页码、公式、数值都要有出处。拿不到就写"待核"，不许补一个像样的数字。
- **区分三层**：作者主张 / 论文证据支持的范围 / 你的推断。三者混在一句话里，卡片就废了。
- **公式克制**：只保留承载机制的符号。为显得专业而堆公式，是在掩盖没想清。
- **故事标注**：虚构例子必须写明"虚构类比，非论文原例"，否则以后会被自己当成事实引用。
- **中文优先**：正文用简明中文，关键术语附英文原词。

## 与文献工作流联动

详见 [references/literature-hook.md](references/literature-hook.md)。要点：

- 两种入口：流水线（literature-pipeline）的 cards 阶段（excel 之后），输入 `extract.json` 的 `economic_theories`，报告由 `run.ps1 --report` 落到 `staging/制卡报告.md`（分桶措辞以 `make_cards.py --verify` 实际产出为准）；伴读（labor-economics-reading）第 5 阶段（研究笔记之后），输入精读与研究笔记产物中「本文真正用到的理论」，报告写在当次阅读产物目录。
- 触发分界：说「只制卡」且已有流水线上下文（extract.json/制卡任务书）→ literature-pipeline；无上下文、直接把理论沉淀入库 → 本技能；「文献学习层/伴读」→ labor-economics-reading。
- 产出：卡片进库（按书架落位）+ `制卡报告.md`（伴读侧列新建 / 跳过 / 并入 / 建链四类清单）。
- 若已有理论在库中：**明确跳过并说明原因**，在报告里列出"跳过清单"，不静默略过。

## 命令速查

```bash
# 库根解析顺序：KCARD_HOME > DSH_CARDS_HOME > 默认 ~/Desktop/知识卡片库
python scripts/kcard.py init                        # 初始化库（建目录 + 建书架）
python scripts/kcard.py check --title "吸收能力" --en "Absorptive Capacity"
python scripts/kcard.py ingest 卡片.md --shelf 知识转换
python scripts/kcard.py shelves                     # 书架分布
python scripts/kcard.py shelf T-0007 知识转换        # 改书架并移动文件
python scripts/kcard.py taxonomy add 数字经济 --desc "平台与数据要素" --keywords 平台 数据要素
python scripts/kcard.py taxonomy rename 数字经济 数字与数据
python scripts/kcard.py taxonomy list
python scripts/kcard.py list --shelf 知识转换
python scripts/kcard.py list --type theory
python scripts/kcard.py show T-0001
python scripts/kcard.py alias T-0001 "企业吸收能力"
python scripts/kcard.py reindex
python scripts/kcard.py browse                      # 只重建浏览页
python scripts/kcard.py graph                       # 只重建关系网（2D + 3D）
python scripts/kcard.py doctor

# 出卡 · 单页可读版（默认，日常看这一版）
python scripts/render_sheet.py T-0001               # → rendered/T-0001-sheet.html
python scripts/render_sheet.py T-0001 --out a.html  # 指定输出路径

# 出卡 · 书册版（打印、发人）
python scripts/render_card_single.py T-0001           # → rendered/T-0001.html
python scripts/render_card_single.py T-0001 --edition ledger   # 强制版式
python scripts/render_card_single.py --all            # 全库重出
```

**两条出口的区别**：`render_sheet.py` 一栏到底、无封面、无目录、正文 17.5px，章节顺序就是 md 里的顺序——它是给人从头读到尾的。`render_card_single.py` 是"一本书"，有封面、有目录、双栏密排——它耐看、能打印，但**不适合第一遍读**。

卡片页右下角带一个查看器：**适应窗口 / 实际大小 / 全屏**。默认「适应窗口」——纸面固定 1080 宽，窗口窄了就等比缩，所以整张纸永远在视野里，不会从左边被裁掉。打印（Ctrl+P）时工具条自动隐藏，纸面回到 1:1、A4 分页。
